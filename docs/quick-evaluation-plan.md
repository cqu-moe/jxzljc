# 快速评价方案

2026-10-19 已经用户确认。

## 已确认

- 交付 Tampermonkey 可安装的单文件用户脚本，并发布到公开仓库 `cqu-moe/jxzljc`。
- 批量处理待评条目，按条目 ID 区分同名课程和不同教师。
- 用户统一设置满意度档位、综合评分和评语；不预选用户的实际评价内容。
- 开始前展示完整待评清单和将要提交的内容，确认一次后逐条自动提交。
- 已填写但未提交的评分、综合评分和评语原样保留，只补空白。
- 失败或提交结果不明确时停止，显示失败原因和已完成进度；不自动重试提交。

2026-10-19 补充需求：待评清单默认显示紧凑课程行，展开后可修改指标评分、综合评分和评语；通过复选框决定本次评价哪些条目。默认全选，取消勾选或收起保留临时编辑。草稿仍用于预填，手动修改只影响本次提交，学校本地草稿不被改写。提交前校验所有已选条目，存在错误则展开定位并阻止整个批次。

交互采用分步界面：初始只有一个设置面板（满意度、综合分、评语），右下角「下一步」切换至预览；预览底部为「上一步」和「开始刷课」。往返保留勾选与逐课编辑，修改统一设置或刷新才重置。切换有方向提示和淡入；提交阶段的动效进度条只按服务器核实成功的课程数量推进，保留停止、部分失败与结果不明确状态。键盘和减少动态效果模式下即时显示。

提交记录与可编辑预览分开：固定两行高度，当前课程置顶，新课程进入时滚回顶部。历史记录继续保留，可用滚轮、触屏或键盘滚动查看；失败项保留在最上方，尚未处理的课程不混入记录。

## 范围与验收

- 待评范围：仅当前学期从未提交的条目，排除历史学期、已提交、已审核和被驳回条目。
- 验证边界：通过脚本用户界面验证计划生成、草稿保留、确认后提交、失败停止及进度恢复；使用受控的学校接口响应，真实网站只检查界面和只读数据。
- 开发基线：以初始化提交 `392fe80` 为最终代码审查比较点。

## 实现范围

- 一个无运行时依赖的 `.user.js` 文件，匹配教学评价站点的学生评教页面。
- 页面中提供设置、预览清单、确认开始、停止和结果显示。
- 读取网站当前学期、课程和指标定义，以实际选项计算分数；不硬编码课程、教师、学生资料、指标 ID 或会话凭据。
- 综合评分遵循页面滑块有效范围（当前最大值为 95，初始值 1 不可提交）。不支持的新题型明确停止。
- 使用当前登录态的同源接口，按序提交，并在每次提交后重新查询确认状态。
- 不调用网站会清空整份草稿的提交收尾逻辑；原有草稿全部保留，下次根据服务器状态排除已提交条目。
- 停止时不启动下一条；已发出的请求需确认结果。刷新后不自动继续，重新读取服务器状态再预览。
